Windows Defender Antivirus

Built-in antivirus: real-time protection and definition updates.

Defender Antivirus

Windows Security → Virus & threat protection

The built-in antivirus for Windows — no additional third-party product is required. It lives inside the Windows Security app under Virus & threat protection. The exact label may not read "Defender Antivirus"; the name has changed over time (Windows Defender → Windows Defender Antivirus → Microsoft Defender Antivirus).

Virus & threat protection → Manage settings → Real-time protection

Don't disable your security protection except for temporary troubleshooting — it increases risk, so make sure you know what you're doing. Defender Antivirus operates in real time. Path: Windows Security app → Virus & threat protection settings → Manage settings → Real-time protection.

Windows Firewall monitors inbound and outbound network traffic and blocks anything that doesn't match an allowed rule, forming the first line of defense between this PC and the network.

Firewall & network protection → each network profile

Activating or deactivating a firewall toggles its ability to monitor traffic — turning it off removes protection and leaves the system vulnerable to unauthorized network connections.

Port security

firewall.cpl → Advanced settings → Inbound rules

Port security controls network traffic by selectively opening or closing specific communication ports, to block unauthorized entry and restrict unnecessary network protocols.

That includes Windows Update and domain traffic. If a rarely used PC (conference room, kiosk) has not received patches and then cannot join the corporate network, the 2.2 answer is a firewall filtering those ports — not a BIOS password, an empty logon session, or Guest being disabled.

Part E

File & Folder Permissions

NTFS vs share, attributes, inheritance, Run as admin, and UAC.

NTFS vs. share permissions

Share tab vs Security (NTFS) tab

Share permissions act like a guard at the front gate, controlling who gets in through the network.

Share permissions apply only to network users and only at the folder. A mapped drive is network access, so the Share tab is in play. The share ACEs are Allow or Deny on Read, Change, or Full control. Deny always wins over Allow — that is the permission with priority.

NTFS permissions act like lockboxes inside the house (folder or file, local or network). List folder contents is an NTFS right, not a share right.

If either Share or NTFS denies you, you are out. When both allow but at different levels, take the more restrictive of the two (Read + Modify = Read). Local interactive use ignores Share permissions entirely.

Practice in the 2.2 interactive lab — click NTFS vs. share permissions in the topic list.

File and folder attributes

File → Properties → Attributes · attrib

File and folder attributes are metadata flags stored by the file system that define specific operating behaviors and access characteristics — such as read-only, hidden, archived, or encrypted.

The attrib command displays or changes those flags. Common switches: read-only (R), archive (A), system (S), hidden (H). + turns an attribute on; - turns it off. Put the flag before the path:

attrib +R [drive:][path][filename]

Wrong order: attrib file.txt +R or attrib /R file.txt.

Key Takeaways for Practice Exams

  • Local Access: Ignore Share permissions entirely; take the NTFS permission as-is.

  • Remote Access: Compare Share vs. NTFS and pick whichever one is more limiting:

    • Share (Read) + NTFS (Modify) = Read (Read is more restrictive than Modify)

    • Share (Full Control) + NTFS (Read) = Read (Read is more restrictive than Full Control)

Practice in the 2.2 interactive lab — click File and folder attributes in the topic list.

Inheritance

Security tab → Advanced → Inheritance

Permission inheritance is a mechanism where files and subfolders automatically receive (inherit) the access permissions of their parent folder.

Propagation is the same idea said the other way: permissions on the parent folder travel down to children created inside it.

Explicit permissions (set on the object itself) beat inherited ones. Precedence:

Explicit Deny > Explicit Allow > Inherited Deny > Inherited Allow

So “inherited permissions take precedence over explicit” is false.

Copy and move change whether NTFS permissions stick or reset:

Same volume — a move keeps the original permissions. A copy inherits the new parent (it does not keep the originals).

Different volume — a copy or a move inherits the new parent. (A cross-volume move is really a copy-plus-delete.)

Part F

Encryption

BitLocker, BitLocker To Go, and EFS.

BitLocker

BitLocker Drive Encryption (not on Home)

BitLocker encrypts an entire volume, protecting all of your data including the OS. It's supported on all Windows editions except Home. If you lose your laptop, it doesn't matter without the password — data stays protected even if the physical drive is moved to another computer.

Practice in the 2.2 interactive lab — click BitLocker in the topic list.

BitLocker-To-Go

BitLocker To Go on removable drives

The same BitLocker protection, applied to encrypt removable USB flash drives.

Practice in the 2.2 interactive lab — click BitLocker-To-Go in the topic list.

Encrypting File System (EFS)

File → Properties → Advanced → Encrypt contents (NTFS, not Home)

EFS encrypts at the file-system level and requires NTFS. It's supported on all Windows editions except Home. It uses your username and password to derive the encryption key — so an administrator password reset will make EFS-encrypted files inaccessible.

Practice in the 2.2 interactive lab — click Encrypting File System (EFS) in the topic list.
