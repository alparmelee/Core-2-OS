4.3

Backup and Recovery Best Practices

Backup types, restore methods, testing frequency, rotation schemes, and the 3-2-1 rule for resilient data protection.

Part A

Backup types

How much data each backup captures — and the trade-off between backup speed, storage, and restore time.

Full backup

Backs up all system data — including the OS, applications, and user files — in a single set.

RestoreFastest — only one backup set needed
BackupLongest backup time
StorageHighest capacity required

Incremental backup

Backs up only files created or modified since the last backup — whether that last backup was full or incremental.

BackupFastest daily backup speed; minimal storage
RestoreRequires the original full backup plus every subsequent incremental in sequence

Differential backup

Backs up all data that has changed since the last full backup.

BackupDaily sets grow larger over time
RestoreOnly two sets needed — the full backup and the latest differential

Synthetic full backup

Creates a new full backup synthetically by consolidating existing full and incremental/differential backup sets locally — rather than pulling a fresh full backup over the network.

Reduces network bandwidth and saves time while still yielding a low restore time comparable to a true full backup.

  • Bandwidth savings
  • Backup appliance
  • Consolidation
Part B

Recovery methods

Where restored data lands — and how to validate backups before you need them.

In-place / overwrite restore

Restores data directly to its original location, replacing and overwriting any existing files currently on the system.

Example: System re-imaging that returns a machine to a known-good state. Fastest path to production but destroys current data on the target — use only when that is intentional.

Alternative location restore

Restores files to a separate designated path or device rather than overwriting existing data.

Allows technicians to verify file integrity, compare versions, or preserve active production data while recovering select files from backup.

Frequency and testing

Regular recovery testing and audits should be conducted to simulate file or system restoration — verifying data integrity and identifying potential restoration failures before an actual system outage occurs.

A backup that has never been tested is an assumption, not a guarantee. Schedule test restores on a defined cadence and document results.
Part C

Backup rotation and location

Where backups live, how long they are retained, and frameworks for layered protection.

Onsite vs. offsite

Onsite

Local backups provide high bandwidth, rapid recovery times, and no extra maintenance fees — but remain vulnerable to localized physical disasters (fire, flood, theft).

Offsite

Backups stored in a secondary facility or cloud protect against site-wide disasters by allowing recovery from anywhere — though transfers depend on internet or WAN links.

Grandfather-Father-Son (GFS)

A structured rotation strategy that layers backups over distinct time intervals:

Grandfather

Monthly full backups, often archived or sent offsite long-term.

Father

Weekly backups (e.g., full or differential).

Son

Daily backups (e.g., incremental or differential).

3-2-1 backup rule

A foundational backup framework requiring:

  • 3 total copies of critical data — one primary operational copy and two backups
  • 2 different types of storage media (e.g., local hard drive, tape, NAS)
  • 1 copy kept offsite (e.g., remote data center or cloud storage)

Designed so no single failure — hardware, site disaster, or ransomware — destroys all copies at once.
