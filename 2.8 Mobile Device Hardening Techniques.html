2.8

Mobile Device Hardening Techniques

Encryption, screen locks, patching, endpoint security, and MDM policies that protect smartphones and tablets.

Part A

Hardening techniques

Core device protections — encryption, locks, and managed configuration.

Device encryption

Encrypts all device data while the phone retains the decryption key.

  • iOS 8+ — personal data is encrypted using the passcode.
  • Android 5.0+ — typically has encryption enabled by default.

Screen locks

Restricts physical access to a device using various authenticators:

  • Facial recognition
  • PIN codes
  • Fingerprint
  • Pattern / swipe
  • Facial recognition — unlocks using facial scans.
  • PIN codes — unlocks via a user-defined Personal Identification Number.
  • Fingerprint — uses a built-in biometric fingerprint reader.
  • Pattern / swipe — unlocks by drawing a specific pattern on the screen.

Configuration profiles

Pre-defined system configurations pushed to devices via Mobile Device Management (MDM) platforms — such as Microsoft Intune or Apple Configurator — to streamline setup, corporate email deployment, and security settings like mandatory lock screens and encryption.

Part B

Patch management

Keeping the OS and apps current to close known vulnerabilities.

OS updates

Regular operating system updates that deliver new features, stability fixes, and critical security patches to prevent vulnerabilities.

Application updates

Ongoing updates for installed applications to maintain current feature sets and resolve security bugs.

Part C

Endpoint security software

Mobile-specific protections against malware, unsafe content, and network threats.

Antivirus & anti-malware

Protects against malicious software.

iOS

Closed, tightly regulated ecosystem. Malware must exploit system vulnerabilities to infect a device.

Android

Open platform — apps can be installed from external sources, increasing malware risk. Third-party protection available.

Content filtering

Restricts device access to unauthorized or hazardous websites and applications.

Firewalls

Mobile operating systems generally do not include native firewalls, as most network traffic is outbound. Third-party mobile firewall apps exist (primarily for Android), while enterprise network firewalls regulate application traffic centrally.

Part D

Locator applications & remote wipes

Find lost devices or erase them when recovery isn’t possible.

Locator applications

Utilizes built-in GPS and location features to locate lost or stolen devices on a map, sound alerts, or display contact messages remotely.

  • Find My (iOS)
  • Find My Device (Android)

Remote wipes

Allows administrators or owners to wipe all data remotely if a lost device cannot be recovered.

Part E

Failed log-in attempt restrictions

Platform-specific responses to repeated wrong passcodes.

iOS

Automatically erases all local data after 10 consecutive failed passcode attempts.

Android

Locks the device following repeated failed attempts, requiring a Google login or triggering a full device wipe.

Part F

Policies and procedures

Enterprise frameworks for managing and securing mobile endpoints.

MDM (Mobile Device Management)

Provides centralized administration for mobile endpoints, enabling remote control over the whole device or an enterprise partition, enforcing access controls, and setting policies for apps, cameras, and data.

BYOD vs. corporate-owned

Bring Your Own Device

Policies to manage employee-owned (BYOD) and company-owned endpoints under uniform organizational security rules.

Profile security requirements

Mandates access control standards across deployment profiles, such as forcing minimum screen lock criteria and PIN complexity.
