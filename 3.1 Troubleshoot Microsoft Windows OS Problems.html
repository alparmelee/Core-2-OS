Troubleshoot Microsoft Windows OS Problems

BSODs, boot failures, performance issues, service errors, memory warnings, and domain-related slowdowns — causes and fixes.

Part A

Crashes and boot failures

When Windows stops, fails to start, or cannot find the operating system.

Blue screen of death (BSOD)

Stop error

Causes can stem from bad hardware, bad drivers, or application issues that prevent the OS from continuing.

Troubleshoot:

  • Attempt to use Last Known Good Configuration
  • Perform a System Restore
  • Roll back recently installed drivers
  • Use Safe Mode to resolve normal startup issues
  • Reseat components to ensure good connections
  • Run hardware diagnostics to test CPU and RAM

Refer to the QR code, stop code (e.g., kernel mode heap corruption), and windows.com/stopcode on-screen details for targeted fixes.

Boot issues

Check for missing OS/bootloader issues or dual-boot conflicts. Remove any attached non-bootable media.

Repair options:

  • Run Startup Repair
  • Use bootrec /rebuildbcd via the Recovery Console command prompt to repair the Windows Boot Configuration Database (BCD)

Use Startup Repair if the system boots exclusively into Safe Mode or if files and directories were moved.

“No OS found”

Caused by bootloader corruption, dual-boot overwrites, or missing boot files.

Fix: Unplug non-bootable media and drives. Run Startup Repair or manually repair the boot database using bootrec /rebuildbcd from the Recovery Console command prompt.

Part B

Performance and stability

Slowdowns, unexpected shutdowns, memory pressure, and clock sync problems.

Degraded performance

Use Task Manager (Processes tab and 60-second Performance tab view) to identify resource-hogging apps.

Additional checks:

  • Check Windows Update for OS bug patches
  • Verify adequate free disk space
  • Run defrag if using an HDD
  • Check power source connections on laptops to avoid power-throttling
  • Run an antivirus scan to clear viruses and malware

Low memory warnings

Sort Task Manager by the Memory column to locate memory-draining programs. Save files and close or restart open programs.

Verify and manage virtual memory (paging file configuration) under:

System > About > Advanced system settings > Performance Settings > Virtual Memory

Frequent shutdowns

Run full hardware diagnostics (motherboard, CPU, RAM) via UEFI/BIOS, motherboard tools, or Windows Memory Diagnostics.

Check system file integrity with sfc (System File Checker) and scan for malware.

Note: Unscheduled or random system stops and application failures require hardware diagnostics and system integrity scans.

System instability

Occurs randomly without warning.

Troubleshoot with:

  • Full hardware diagnostics via UEFI/BIOS or motherboard tools
  • Windows Memory Diagnostics
  • sfc (System File Checker)
  • Anti-malware scan

Time drift

Caused by hardware inaccurate timekeeping.

Resolve by navigating to Settings > Time & Language > Date & Time and enabling Set time automatically (and automatic daylight saving adjustments) to synchronize with central time servers, or perform a manual sync.

Part C

Services, applications, and peripherals

When services fail, apps crash, USB endpoints max out, or domain profiles load slowly.

Services not starting

Verify device status in Device Manager — update, roll back, or replace drivers.

Open the Services app to attempt manual service starts, adjust account authentication permissions, and verify service dependencies.

Run sfc for built-in Windows services or perform an admin-permission reinstall for third-party application services.

  • Device Manager
  • services.msc
  • sfc /scannow

Applications crashing

Inspect log entries in Event Viewer or use Reliability Monitor to identify failure causes and performance trends over time.

Reinstall the failing application if necessary.

USB controller resource warnings

This occurs when connecting devices that exceed the USB controller’s available endpoints.

Fix: Disconnect the device and move it to a different USB port or controller. Balance endpoint loads by plugging USB 2.0 devices into USB 2.0 controllers and USB 3.0 devices into USB 3.0 controllers.

Slow profile load

Typically caused by network latency or WAN congestion when syncing roaming user profiles to a remote domain controller.

Domain administrators can resolve this by repairing or optimizing local domain controllers.
