Part A

System Requirements

Check architecture, memory, CPU, storage, and license hardware before you click Install.

32-bit vs. 64-bit dependent application requirements

OS bitness must match the app and its drivers

Hardware drivers are specific to the OS version — 32-bit (x86) or 64-bit (x64). A 32-bit OS cannot run 64-bit apps. A 64-bit OS can run 32-bit apps.

On 64-bit Windows, 32-bit programs run through WOW64. They work, but they stay limited to 32-bit address space. Device drivers are stricter: a 32-bit driver will not load on a 64-bit OS.

Dedicated vs. integrated graphics card

Shared system RAM vs. its own VRAM

Integrated: CPU and GPU are the same chip and share system memory for graphics — common in laptops. Dedicated (discrete): has its own VRAM, for high-end graphics requirements.

Integrated is cheaper and easier on battery. Dedicated (a separate card) is what you want for gaming, 3D, CAD, and heavy video work.

Practice in the 1.10 interactive lab — click Dedicated vs. integrated graphics card.

Video random-access memory (VRAM) requirements

Framebuffers, textures, 3D geometry

VRAM is high-speed memory dedicated exclusively to storing graphical assets — framebuffers, 3D geometry, textures, and depth buffers. Dedicated cards have built-in VRAM; integrated graphics borrow a portion of main system RAM, reducing what is left for other applications.

RAM requirements

App + OS + everything else already open

A critical specification — the application may perform poorly or not at all without enough RAM. This is above and beyond the OS requirements, depends on the application, and must account for every other running application.

Practice in the 1.10 interactive lab — use the RAM budget calculator.

Central processing unit (CPU) requirements

Higher GHz is a rough “faster” number

Processing speed is usually measured in gigahertz (GHz) — a broad measurement where higher numbers mean faster CPUs. Requirements vary a lot by application: word processing needs far less than video editing.

Core count and generation also matter, but CompTIA still wants you to treat the published GHz minimum as a go/no-go check for the workload.

Practice in the 1.10 interactive lab — match workload type to available CPU speed.

External hardware tokens

Dongle — app runs only while it is plugged in

Used to manage application usage and limit access to authorized users — the application will only operate with the hardware token connected. Commonly a USB device. Can be a challenge to manage, and is often used with high-end software that carries high per-seat licensing costs.

Practice in the 1.10 interactive lab — toggle the USB hardware token on CAD Suite Pro.

Storage requirements

Install size is not the whole story

A drive-space concern with two parts: the initial installation space requirement, and ongoing application-use requirements. Some applications consume a lot of additional storage after installation — so the initial install size may not be the most important number.

The installer package itself also eats space if you copy it onto C: first. Leave the source on USB or a network share and install only the program files locally. That is different from putting the finished application on a share — a video editor on the LAN would be slow and fragile.

Practice in the 1.10 interactive lab — slide months of use and watch caches grow past free space.

Application to OS compatibility

Architecture, dependencies, and API version

The software must match the system architecture (32-bit vs. 64-bit), have its software dependencies satisfied, and meet the operating system API requirements of the host environment in order to run properly.

Typical missing pieces: Visual C++ Redistributable, a .NET runtime, or an OS build below the app’s minimum.

Part B

Deployment Methods

How the bits actually get onto the PC — disc, USB, ISO, a network share, a download, or a cloned image.

Physical media vs. mountable ISO file

Optical / USB vs. a sector-by-sector image file

Physical media — optical disc, USB drive, etc. — is increasingly rare. An ISO is an optical disk image: a single file that is a sector-by-sector copy of a disc's files and folders, which can be mounted directly.

On Windows, right-click an .iso and choose Mount to get a virtual drive letter with no disc in the tray.

A network share is another install source: copy the setup folder to a file share and run it from a UNC path or mapped drive. That keeps the large installer off the workstation. If USB setup fails because the local disk is full, CompTIA wants you to change the source to a share — not install the app itself onto the share, compress the files, or copy payloads by hand into Program Files.

Practice in the 1.10 interactive lab — compare Insert disc vs Mount ISO.

Downloadable package

Manufacturer site or official store only

Get the installer direct from the manufacturer or a centralized app store — and avoid third-party download sites, which carry a higher risk of tampered or bundled software.

Practice in the 1.10 interactive lab — switch the download source to a third-party site and read the warning.

Image deployment

One master image → many identical PCs

Create a standard OS "master image" (gold image) and clone it across many target systems over the network or via physical media. A perfect fit for virtual machines, and very fast to deploy at scale.

Part C

Impact Considerations

A new app is not just an installer — it can hurt the device, the network, the job, and the business.

Device impact considerations for new applications

Crashes, slowness, or lost files after an upgrade

Think through what a new application or upgrade can do to the device it runs on: it may stop working after an upgrade, cause slowdowns, or even delete files.

Pilot first, keep the old installer for rollback, and back up user data before a major version jump.

Practice in the 1.10 interactive lab — open Device impact considerations for new applications.

Network impact considerations for new applications

Firewall, VPN, and file-share rights

A new application often needs access to internal services, plus the rights and permissions to reach file shares — both of which need to be planned and provisioned.

A share can also hold the installer (source). That is not the same as installing the program to the share as its home folder. Use the share to host setup.exe; still put a disk-heavy app on the local drive once there is room.

Practice in the 1.10 interactive lab — toggle internal services and share permissions.

Operation impact considerations for new applications

Time-sensitive jobs vs. a changed workflow

Many jobs are time-sensitive. An updated application may require a change to an existing workflow — or it may not work with that workflow at all.

If the job is nightly or shift-based, schedule the change outside that window and retrain before go-live.

Practice in the 1.10 interactive lab — flip time-sensitive and workflow-changed toggles.

Business impact considerations for new applications

One outage can stall the next department

Critical business processes are sensitive to downtime and outages. A change to one application can create issues elsewhere — other parts of the business rely on its results.
